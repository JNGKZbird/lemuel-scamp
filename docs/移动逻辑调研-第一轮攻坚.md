# 捣蛋鬼计划 · 移动逻辑调研（第一轮攻坚）

> 调研日期：2026-10-17 ｜ 性质：设计参考，未拍板
> 范围：桌面宠物的移动与行为系统
> 重点：怎么走、怎么决定去哪、怎么避免"左右乱跑"与"上下滑步"

**本项目现状**：能天使/新约双独立悬浮窗；Relax / Move / Interact 已接；转身 0.15s Linear；戳一戳已打断移动；当前巡逻为硬编码（走→屏幕边→停 1.2s→转身→反向）。尺寸 16.3% 屏高、走速按触地段速度联动。

---

## 0. 摘要（先看这页）

- **共识架构**：输入/窗口 → 行为决策 → 动作状态机 → 渲染/物理。分层、数据驱动是普遍做法。
- **桌宠的"AI"通常不复杂**：频率加权随机＋条件门控＋冷却，就是 Shimeji 这类经典桌宠的全部自主逻辑。
- **状态机光有状态列表不够**：需要优先级、最小显示时长、持续条件、退出动作、自动回退，否则会闪切或卡死。
- **移动的硬结论**：纯侧视美术下，**水平位移用侧视行走，垂直位移用专用动作**（攀爬/浮空/跳跃/拖拽）。把侧视走路拿去走上下，滑步是结构性的，调参救不了。真正的四方向行走需要四向美术或俯视/45° 视角。
- **对项目的含义（建议）**：第一轮做"水平生活圈＋三层骨架"（idle / stroll / sit / sleep）；垂直主动移动留到第二轮作为明确的新产品决策；光标关注按用户要求先保留（属于游戏外新逻辑）。
- **Agent 化接入点**：行为调度器。LLM 只输出"意图"，不直接驱动骨骼。

## 2. 参考系速览

> 以下为检索摘要＋原始链接；关键数字建议以仓库源码复核。

### 2.1 pet-engine（npm，Web/Electron 方向）
- 主循环整合 AnimationPlayer、StateMachine、BehaviorController、PhysicsController、InteractionSystem、Renderer、EventEmitter——**行为/动画/物理/交互分离**。
- BehaviorController 的自主行为只有两类：`idle` 与 `path`（路径/游荡）。参数化：速度范围约 80–150、持续 3000–8000ms、休息概率 0.3、idle 持续 2000–5000ms。
- StateMachine 管**动作状态与合法转移**；AnimationPlayer 管 fps/帧范围/循环/完成回调。
- PhysicsController 支持重力、终端速度、jump 脉冲；InteractionSystem 有拖拽阈值与释放后的 stay/physics 选择。
- **启示**：移动逻辑应是"参数化行为表"，不是写死坐标。

### 2.2 desktop-pet（duzexu）：普通规则 vs 状态型规则
- **普通规则**：事件 → 匹配 → 执行动作（一次性触发）。
- **状态型规则**：进入条件持续成立（`sustainMs`）后触发；退出条件持续成立后执行退出动作。典型用例："鼠标靠近 3 秒后问候/跟随，远离 3 秒后回默认"。
- 运行期维护每规则状态（conditionTrueSince / active / exitTrueSince），激活态压制普通规则；鼠标静止时用 500ms 定时器兜底退出计时。
- **启示**：像"靠近后跟随""长时间无操作后睡觉"这类行为，用状态型规则比事件回调稳。

### 2.3 clawd-on-desk：双窗口与优先级
- **渲染窗口**与**输入窗口**分离：透明大窗只负责画动画并永久忽略鼠标；小输入窗用 hitbox 形状接收事件。
- 显示状态优先级：`error(8) > notification(7) > sweeping(6) > attention(5) > carrying/juggling(4) > working(3) > thinking(2) > idle(1) > sleeping(0)`。
- 有**最小显示时长**防闪切；一次性状态结束后自动回退。
- 睡眠是序列推进：鼠标静止 20s → idle-look → 60s → yawning → dozing → 10min → collapsing → sleeping；鼠标移动触发 waking(1.5s)。
- **启示**：我们已有"一个窗口＋动态命中框"，方向一致；优先级/最小时长/序列这些规则值得借。

### 2.4 ClawPuter（macOS 陪伴型）
- 全局鼠标监听 → 窗口平滑跟随（带缓动，不严格贴合），停在光标附近偏移 **80–120px**。
- 优先停在屏幕边缘或窗口边框附近，避免遮挡内容；透明、置顶、点击穿透。
- idle 判定：光标停止约 3s 进入 idle；光标移动进入 walk；点击触发 happy；Timer 驱动睡眠。
- **启示**：如果以后做"跟随光标"，这就是一组合适的默认参数。

### 2.5 Shimeji：频率加权行为图（经典参考）
- 配置：`actions.xml`（能做什么：Stay / Move / Animate / Sequence）、`behaviors.xml`（什么时候做）。
- 每个 Behavior 有 **Frequency 权重**；`Condition` 门控（在 floor / wall / ceiling / 窗口边框 / 工作区边缘等）；`NextBehaviorList` 把行为串成图。
- 条件与参数是 JavaScript 表达式：`${...}` 每实例求值一次，`#{...}` 每 tick 求值。
- 拖拽/扔出有物理语义：扔出读取光标最近速度（`cursor.dx/dy`）；必备动作包括 ChaseMouse / Fall / Dragged / Thrown。
- **启示**：不需要行为树；一张"行为表＋条件＋权重＋后续链"就足够撑起生活感，而且可数据化调参。

### 2.6 VPet（WPF 开源，属性驱动）
- 数据 / 交互 / 动画分层；官方 README 提到动画最多 32 种 × 4 状态 × 3 类型 = 384 个。
- 有饱食度、心情、体力一类属性，行为与属性联动（第三方文章称其行为调度为 FSM/行为树雏形，**未在官方文档中核实到具体 StateMachine 类**，仅作思路参考）。
- **启示**：长期"活感"来自慢变量（心情/体力/作息）驱动行为权重，而不是纯随机。

### 2.7 2D 侧视与垂直移动（美术实践，关键）
- 纯侧视桌宠**不应**把"上下移动"做成"侧视走路"：侧视行走的脚部接触方向是水平的，垂直位移没有对应地面支撑点，必然滑步。
- 推荐映射：左右→侧视走；上下→攀爬 / 浮空 / 跳跃 / 被拎起等专用状态；指针注视是独立"看的方向"，不产生位移。
- 真四方向行走需要俯视或斜 45° 的四套方向锚点（front/back × left/right），不能把侧视走路旋转 90°。
- 防滑步检查：动作向量匹配位移向量；支撑脚钉地；步幅与速度同步；边缘/碰撞切"受阻"状态；转身先对齐朝向再换图；锚点与脚底基线统一。
- **对本项目**：我们只有一套侧向 Move 与 Relax/Sit/Sleep/Interact，没有攀爬/浮空/跳跃动画——**第一轮就不该做垂直主动移动**，除非我们决定新增"游戏外"的浮空/跳跃表现。

### 2.8 Desktop Goose / GooseAI
- 社区可查的是 GooseAI 模组：用 OpenAI 兼容接口，`systemPrompt` 定人格、`chanceToSpeak`（默认 0.05）控制闲话概率；底层行为系统未公开。
- **启示**：Agent 化可以后接在行为调度器上；"像宠物"先靠行为设计，不靠大模型。

## 3. 综合发现

| 设计维度 | 共识做法 | 对我们的含义 |
|---|---|---|
| 架构 | 输入/行为/动画/物理分层 | 沿用我们提议的三层：Locomotion / Scheduler / Presentation |
| 行为选择 | 加权随机＋条件门控＋冷却 | 不用行为树，先做参数表 |
| 状态管理 | 优先级＋最小显示时长＋退出条件＋自动回退 | 必须现在就定，否则后期难补 |
| 持续行为 | 状态型规则（sustainMs） | "看光标/跟随/睡眠"以后用它 |
| 移动语义 | 水平侧视走；垂直专用动作 | 第一轮只做水平；垂直待产品决策 |
| 失控保护 | 用户输入优先、可中断、边缘受阻状态 | 与现有拖动/戳一戳一致 |
| 长期活感 | 慢变量（心情/体力/作息）驱动权重 | 为未来 Agent 化预留状态量 |
| Agent 接入 | 调度器出意图，不直接动骨骼 | 与远期 Agent 化天然对齐 |

## 4. 游戏原逻辑 vs 桌宠新逻辑（边界要写清）

| 类别 | 内容 | 来源 |
|---|---|---|
| 游戏原逻辑（复刻） | Move / Relax / Sit / Sleep / Interact 动画；走速与尺寸；战斗转身 0.15s Linear | 官方资产与客户端数据 |
| 桌宠新逻辑（我们自定） | 游走调度、生活节奏、作息、光标关注、垂直移动、双角色互动、隐藏/召回、Agent 行为 | 产品设计 |

**建议**：把"新逻辑"集中放在 Scheduler 层，渲染/动画层保持"只是执行"，这样以后每加一条新逻辑都容易回退与调参。

## 5. 第一轮攻坚提案（待拍板）

### 5.1 架构
- **Locomotion**：位置/速度、屏幕边缘（角色零件贴边）、转身、朝向、动画选择；不做决策。
- **Scheduler**：加权随机＋条件＋冷却；输出"意图＋目标点＋时长"；参数表化。
- **Presentation**：动画状态机（合法转移、最小停留、一次性动画回退）。

### 5.2 行为集（建议）
| 行为 | 动画 | 说明 |
|---|---|---|
| 待机 | Relax（循环） | 主场；时长 2–5s |
| 溜达 | Move | 水平随机目标点；3–8s；边缘触发转身 |
| 坐下 | Sit | 低频长行为（本体 8.33s 动画可用作久坐） |
| 睡觉 | Sleep | 长无人值守或夜间；可先不做 |
| 戳一戳 | Interact | 已实现；优先级高于调度 |
| 拖拽 | — | 已实现；控制权归属最高 |

### 5.3 状态表草案
| 状态 | 动画 | 进入 | 退出 | 可被打断 |
|---|---|---|---|---|
| idle | Relax | 默认 | 超时→stroll/sit | 是 |
| stroll | Move | 调度 | 到点/边缘→idle | 是 |
| sit | Sit | 调度 | 播完→idle | 是 |
| sleep | Sleep | 长闲置/夜间 | 用户输入→idle | 是 |
| poke | Interact | 点击 | 播完→idle | 拖拽可打断 |
| drag | — | 指针按下 | 松开→idle | — |

### 5.4 参数表草案
| 参数 | 建议初值 |
|---|---|
| idle 时长 | 2–5s |
| stroll 时长 | 3–8s |
| stroll 目标点 | 屏宽 ±10–30% 内随机 |
| sit 概率/冷却 | 低概率；冷却 ≥60s |
| 边缘行为 | 到边→idle 1.2s（现状） |
| 行为权重 | 待你定"生活节奏" |

### 5.5 验收
- 不卡死、不丢窗；任何行为可被拖动/戳一戳立即打断。
- 水平移动无滑步（速度=触地速度×scale）；边缘以零件为准。
- 行为有变化但不癫痫；参数可调。
- 垂直主动移动**不在本轮**（保持拖拽）。
